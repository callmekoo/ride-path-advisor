## Что построено

Команды: `fetch-region`, `build-graph`, `route`, `eval`, `import-tracks`, `match`, `pop-map`, `enrich`.

- **Граф** (`osm/`, `graph/`): рёбра — куски OSM-пути между узлами разреза, степень 2 не
  схлопывается; зимники, автомагистрали, стройки, лестницы выброшены; только главная компонента.
  Покрытие — 6 классов уверенности с выводом `surface` → `tracktype` → класс дороги.
- **Ядро** (`kernel/`): `Graph.route(src, dst, w)`, `Graph.sssp(src, w, aux, max_cost, reverse)`.
- **Веса** (`routing/cost.py`): `Prefs{avoid_major, surface, familiarity, forest, hills}`;
  `w = len · (1 + класс дороги + незнакомость + не-лес + подъём) · покрытие · ограничения`, потолок ×50.
- **Генератор** (`routing/generate.py`): 36 попыток (1–3 опорные точки × 12 азимутов) в пуле
  потоков; обход со штрафом ×20 за повтор рёбер и запретом разворота на опорной точке; подгонка
  масштаба до попадания в длину; обрезка хвостов; оценка; жадный отбор с перекрытием < 0,4.
- **Треки** (`tracks/`, `match/`): архив Strava читается по позициям колонок (заголовки
  локализованы); берутся только велозаезды (`RIDE_TYPES` в `tracks/ingest.py`), пропущенные типы
  печатаются. Привязка — Valhalla в процессе, результат хранится по OSM-путям
  (`data/match/matched.npz`) и не зависит от версии графа; `rides[e]` — число разных заездов по ребру.
- **Обогащение** (`enrich/`): узлы у воды (150 м) из OSM; лес из ESA WorldCover; высоты из
  Copernicus GLO-30 (пробы каждые ≤50 м вдоль рёбер). Растры читаются по сети, локально не кешируются.
- **Оценка** (`eval/`): 9 эталонных запросов, пороги: ≥2 кандидата, длина в допуске,
  повторы ≤5%, ≤5 с.

Замеры на реальном графе (803 тыс. узлов, 1,06 млн рёбер): запрос на 3 кольца — 0,5–0,8 с;
сборка графа 12 с; привязка 1761 сегмента 40 с; обогащение 97 с.

## Данные

Всё в `data/` (не в git). Полная пересборка с нуля:

```bash
uv run rpa fetch-region                          # data/osm/region.osm.pbf (нужны сеть и podman либо osmium-tool)
uv run rpa build-graph data/osm/region.osm.pbf   # data/graph/<sha12>-v1, симлинк current
uv run rpa import-tracks                         # data/inbox/* → data/tracks
uv run rpa match                                 # тайлы Valhalla при необходимости → data/match → rides.npy в графе
uv run rpa enrich                                # вода, лес, высоты → файлы в каталоге графа
uv run rpa eval                                  # проверка
```

- `build-graph` сам пересчитывает `rides.npy` из `data/match`; **`enrich` после пересборки графа
  нужно запускать заново**.
- В каталоге графа, кроме массивов графа: `rides.npy`, `water_nodes.npy`, `water.json`,
  `forest.npy`, `prof_off.npy`, `prof_ele.npy`, `ascent.npy`. `Engine` подхватывает то, что есть;
  без файла соответствующее предпочтение просто не действует.
- Сейчас импортирован один архив (1743 заезда, 19,4 тыс. км в регионе). Архив второго
  пользователя — положить в `data/inbox/` и повторить `import-tracks` и `match`.

## Отличия кода от исходного дизайна

Дизайн (`specs/2026-11-10-…-design.md`) писался до реализации. Фактически:

- **Генератор колец** ставит опорные точки геометрически (углы правильного многоугольника с
  привязкой к «приятному» перекрёстку), а не по полосе сетевого расстояния из SSSP. SSSP-полоса
  используется только для A→B с целевой длиной.
- **`RouteSpec` сейчас**: `start`, `end`, `shape`, `length_km`, `prefs`, `via_category` (только
  `"water"`), `n_candidates`. Ещё нет: опорной точки-места, `avoid`, `anchor_candidate` — появятся в M6.
- **Привязка треков**: costing `bicycle` с `ignore_oneways` и `ignore_access`, а не `pedestrian`.
- **Лес**: WorldCover читается в 1/8 разрешения (80 м) со сглаживанием 3×3 вместо полосы ±25 м
  на полном разрешении.
- **Обогащение** лежит в каталоге графа плоско, без подкаталога `enrich/`; расстояния до воды нет,
  только узлы у воды.
- **Оценка кандидата** проще, чем в дизайне: длина, повторы, отношение стоимости к длине, повороты.
- **Не сделано из запланированного для M1–M4**: барьеры на узлах; зоны избегания в весах;
  закоммиченная реальная вырезка для тестов; вывод покрытия из скоростей треков.
- **Тесты ядра** — только из Python; `cargo test` не используется.

## Известные проблемы и что подстроить

- **Набор высоты, вероятно, завышен** в городе и лесу (модель поверхности видит крыши и кроны):
  374 м на 45 км по Екатеринбургу. Сверить с реальными заездами; при необходимости усилить
  сглаживание в `enrich/rasters.py::climb_m`.
- **Режим `paved`** всё ещё пропускает до ~7% «вероятно грунтовых» участков; множитель ×5 для
  `likely_unpaved` мал. Покрытие в регионе размечено плохо (явный асфальт — 11% длины дорог).
- **Маршруты «к воде»** могут дать два кольца к одному и тому же водоёму.
- **Замкнутые пути** (кольцевые развязки): заезд через замыкающий узел приписывается не той дуге.
- **Числа в весах и оценке** — стартовые, по `out/eval.html` всерьёз не подбирались.
- Карты `out/eval.html` и `out/heatmap.html` глазами проверял только пользователь (M1) — после
  M2–M4 их стоит пересмотреть.

## Оставшиеся этапы

### M5. Веб-API

- Зависимости: `fastapi`, `uvicorn`. Один воркер; `load_engine` при старте; маршруты считаются в
  `ThreadPoolExecutor`. По умолчанию слушать `127.0.0.1`. Логинов нет.
- `src/rpa/api/app.py`, `api/schemas.py`, `api/db.py` (SQLite в `data/`: сохранённые места,
  сессии с последними кандидатами, сохранённые маршруты), `routing/gpx.py`.
- `POST /api/route` (`RouteSpec` → кандидаты: координаты, признаки, оценка, пометка, название
  цели, профиль высот; у каждого кандидата id), `GET /api/candidates/{id}.gpx`, CRUD
  `/api/places` (место по умолчанию — «дом»), `GET /api/meta` (размер графа, какие данные есть:
  заезды, вода, лес/высоты), команда `rpa serve`.
- Загрузка треков через веб: файл в `data/inbox/`, затем `import-tracks` и `match` отдельным
  процессом; сервер перечитывает `rides.npy`. Можно отложить на конец этапа.
- Тесты: контрактные через `TestClient` на синтетической сетке (`tests/helpers.py::grid_graph`).
- Проверка: `curl` к `/api/route` на реальном графе, GPX открывается в стороннем просмотрщике.

### M6. Разбор текста

- От пользователя нужны: адрес OpenAI-совместимого API, модель, ключ, адрес прокси.
- `src/rpa/nlu/client.py` (httpx, `trust_env=False`; `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY`,
  `LLM_PROXY_URL` — http/https/socks5, прокси только для LLM), `nlu/prompt.py`, `nlu/resolve.py`,
  `osm/gazetteer.py`, `.env.example`.
- **Один вызов LLM** со структурированным выводом (JSON-схема; запасной путь — JSON в тексте,
  проверка pydantic и один повтор). Топонимы — строками в именительном падеже; ищет их сервер.
- Газеттир: все именованные объекты OSM, включая непроезжие (тоннели, станции, вершины,
  водоёмы), в SQLite FTS5; привязка к ближайшему проезжему узлу, предупреждение дальше 500 м.
- Сервер сам задаёт уточняющий вопрос, если старт неизвестен или топоним неоднозначен.
  Порядок выбора старта: названное место → сохранённое место («дом») → клик по карте → вопрос.
- Уточнение («короче», «не через Ревду», «вариант 2, но короче») = предыдущий `RouteSpec` +
  краткая статистика кандидатов + новая реплика → новый полный `RouteSpec`.
- Расширить `RouteSpec`: опорная точка-место, `avoid [{place, radius_m}]` (мягкий множитель ×8 в
  весах), `anchor_candidate`.
- `POST /api/parse` (текст, точка клика, сессия → `RouteSpec` или вопрос).
- Тесты: ~40 русских формулировок → ожидаемые поля `RouteSpec` на записанных ответах;
  `rpa nlu-eval --live` с реальным ключом. Данные треков в LLM не отправляются.

### M7. Веб-интерфейс

Vite + TypeScript + React + MapLibre GL JS (тайлы OpenFreeMap), без роутера и стейт-библиотек.
Чат-панель; разобранный запрос чипами (видно и можно поправить, как сервис понял текст);
карточки кандидатов со статистикой; профиль высот; маркер старта кликом; управление местами;
слой личной теплокарты; атрибуция источников (OSM, Copernicus, ESA WorldCover).
Собранный `web/dist` раздаёт FastAPI.

### M8. Контейнер и документация

Containerfile в три стадии (rust + uv → node → `python:3.14-slim`), один образ для сервера и
пакетных команд; `podman run --userns=keep-id -v ./data:/data:Z -p 8000:8000`. README для
установки с нуля, скрипт обновления данных. Перед первым пушем на GitHub — проверить, что в
истории нет личных данных.

## Окружение разработки

- Fedora, Python 3.14 (uv), Rust через rustup в `~/.cargo`, uv в `~/.local/bin`; `podman` есть,
  `docker` и системного `osmium-tool` нет — `fetch-region` собирает образ `rpa-osmium` сам.
- В окружении задан `HTTPS_PROXY`; httpx и rasterio берут его сами. Для cargo нужен
  `CARGO_HTTP_CAINFO` (см. `CLAUDE.md`).
- `/usr/bin/time` отсутствует — время мерить через `SECONDS` в bash.

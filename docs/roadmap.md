## Что построено

Команды: `fetch-region`, `build-graph`, `route`, `eval`, `import-tracks`, `match`, `pop-map`,
`enrich`, `serve`, `gazetteer`, `nlu-eval`, `sync-tracks`, `update`.

- **Граф** (`osm/`, `graph/`): рёбра — куски OSM-пути между узлами разреза, степень 2 не
  схлопывается; зимники, автомагистрали, стройки, лестницы выброшены; только главная компонента.
  Покрытие — 6 классов уверенности с выводом `surface` → `tracktype` → класс дороги.
- **Ядро** (`kernel/`): `Graph.route(src, dst, w)`, `Graph.sssp(src, w, aux, max_cost, reverse)`.
- **Веса** (`routing/cost.py`): `Prefs{avoid_major, surface, familiarity, forest, hills}`;
  `w = len · (1 + класс дороги + незнакомость + не-лес + подъём) · покрытие · ограничения`, потолок ×50.
- **Генератор** (`routing/generate.py`): 36 попыток (1–3 опорные точки × 12 азимутов) в пуле
  потоков; обход со штрафом ×20 за повтор рёбер и запретом разворота на опорной точке; подгонка
  масштаба до попадания в длину; обрезка хвостов; оценка; жадный отбор с перекрытием < 0,4.
- **Треки** (`tracks/`, `match/`): архив Strava читается по позициям колонок (заголовки
  локализованы); берутся только велозаезды (`RIDE_TYPES` в `tracks/ingest.py`), пропущенные типы
  печатаются. Привязка — Valhalla в процессе, результат хранится по OSM-путям
  (`data/match/matched.npz`) и не зависит от версии графа; `rides[e]` — число разных заездов по ребру.
- **Обогащение** (`enrich/`): узлы у воды (150 м) из OSM; лес из ESA WorldCover; высоты из
  Copernicus GLO-30 (пробы каждые ≤50 м вдоль рёбер). Растры читаются по сети, локально не кешируются.
- **Оценка** (`eval/`): 9 эталонных запросов, пороги: ≥2 кандидата, длина в допуске,
  повторы ≤5%, ≤5 с.

- **Веб-API** (`api/`, `routing/gpx.py`): `create_app(engine, db_path)`; `rpa serve` слушает
  `127.0.0.1:8000`. `GET /api/meta`; `POST /api/route` (тело — `RouteSpec`; ответ: `request_id`,
  кандидаты с GeoJSON-геометрией, статистикой, профилем высот ≤ 500 точек, `warnings`, `message`
  при пустом результате); `GET /api/candidates/{id}.gpx`; CRUD `/api/places` (одно место по
  умолчанию, имена уникальны без учёта регистра). Точка дальше 2 км от дорог → 422, дальше
  500 м → предупреждение. SQLite `data/rpa.sqlite` (`api/db.py`): места и последние 200 запросов
  с кандидатами — `Db.request(id)` отдаёт прошлый `RouteSpec` и кандидатов для уточнений в M6.
  Описание схем — `/docs` у запущенного сервера.

- **`RouteSpec` для запросов словами** (`routing/spec.py`, `generate.py`): `via` — точка, через
  которую надо проехать (кольцо: старт → место → подобранная точка → старт; на тупиковой дороге у
  места разрешён разворот); `avoid` — круги с множителем ×8; `bearing_deg` — кольца только в
  пределах ±45° от азимута.
- **Газеттир** (`osm/gazetteer.py`, `rpa gazetteer`): 21 тыс. мест из OSM (населённые пункты,
  станции, озёра, реки, вершины, парки) в `gazetteer.sqlite` в каталоге графа, сборка 7 с.
  Сравнение без родовых слов («озеро», «город»…), регистра, `ё` и окончаний; тёзки одного вида
  ближе 4 км склеиваются. Порядок: точные раньше неточных, названный вид («озеро …»), важность
  (город, посёлок, прочее, станция, река), расстояние.
- **Разбор текста** (`nlu/`): один вызов LLM → `ParsedRequest` (плоская структура, места —
  строками; промпт в `nlu/prompt.py`); `nlu/resolve.py` без LLM собирает `RouteSpec` или один
  вопрос. Старт: названное место → клик → прежний старт (при уточнении) → место по умолчанию →
  вопрос. Тёзки: берётся единственный в старшем классе либо явно ближайший (вдвое и на 10 км
  ближе следующего), иначе вопрос с вариантами. Клиент (`nlu/client.py`): OpenAI-совместимый API,
  структурированный вывод с откатом на JSON в тексте, один повтор, `trust_env=False`, прокси из
  `LLM_PROXY_URL`. В модель уходят только текст, названия мест и статистика вариантов.
- **`POST /api/parse`**: `{text, click?, request_id?, picks?, understood?}` →
  `{spec | null, question | null, understood, warnings}`. `request_id` делает реплику
  уточнением прошлого запроса; `understood` (вернуть то, что пришло в прошлом ответе) пересобирает
  запрос без вызова модели — так отвечают на вопрос: кликом (`click`) или выбором варианта
  (`picks: {question.about: option}`). Без LLM — 503, ошибка модели — 502.
  `/api/meta` сообщает `has_gazetteer` и `has_llm`.
- **Сохранённые маршруты**: `POST /api/routes {candidate_id, name?}`, `GET /api/routes`,
  `GET /api/routes/{id}` (с `spec` и `candidate`), `GET /api/routes/{id}.gpx`, `DELETE`. Маршрут
  копируется из кандидата и не зависит от очистки последних 200 запросов.
- **`GET /api/heatmap`**: проеханные дороги как GeoJSON, по одному `MultiLineString` на уровень
  (1, 2–4, 5–14, 15–49, 50+ заездов); 2,2 МБ, по сети 0,55 МБ (gzip); собирается при первом
  обращении. Та же функция (`viz/heat_page.py::ridden_roads`) рисует `rpa pop-map`.
- **Заезды без перезапуска**: `rpa match` заменяет `rides.npy` целиком; сервер перед
  `/api/route`, `/api/meta`, `/api/heatmap` сверяет время изменения и номер файла и, если он
  новый, подменяет счётчики (`api/app.py::_RidesFile`). Файл под другой граф игнорируется
  с записью в лог. Новый **граф** сервер не подхватывает — нужен перезапуск.
- **Загрузка треков** (`api/jobs.py::TrackImport`): `PUT /api/tracks/files/{name}` — тело запроса
  и есть файл, пишется потоком в `data/inbox` (временное имя с точкой, затем переименование;
  `.zip`, `.gpx`, `.fit`, `.tcx` и `.gz`; до 4 ГБ); `POST /api/tracks/import` запускает
  `python -m rpa sync-tracks` отдельным процессом, вывод — в `data/jobs/tracks.log`;
  `GET /api/tracks` — состояние, хвост журнала, файлы на сервере. Один запуск за раз, загрузка
  во время обработки — 409. Каждый запуск обрабатывает весь inbox заново.
- **`rpa sync-tracks`** = `import-tracks` + `match`. **`rpa update`** = `fetch-region` →
  `build-graph` → `gazetteer` → `enrich` (`--skip-fetch`, `--pbf`, `--no-rasters`).
- **Образ** (`Containerfile`, 0,83 ГБ): сборка — `python:3.14-slim` + uv + rustup, страница —
  `node:24-slim`, итог — `python:3.14-slim` + `osmium-tool`, `.venv`, `web/dist`;
  `ENTRYPOINT rpa`, по умолчанию `serve --host 0.0.0.0`; данные в `/data`. Сервер в контейнере
  на реальном графе занимает 0,52 ГБ памяти.
- **Веб-интерфейс** (`web/`: Vite, React, TypeScript, MapLibre GL JS 6, тайлы OpenFreeMap).
  `npm run build` кладёт страницу в `web/dist`, её раздаёт `rpa serve` с корня (`RPA_WEB_DIR`
  меняет каталог). Слева панель: диалог, чипы «как понят запрос» (крестик снимает условие,
  «Изменить» открывает редактор длины, покрытия, рельефа и трёх ползунков), карточки вариантов
  (длина, набор, доли леса / знакомых / крупных дорог / грунта, GPX, «Сохранить»), профиль высот
  (наведение двигает точку по карте); вкладки «Места», «Сохранённые» и «Треки» (загрузка файлов,
  ход обработки, журнал); флажок «Мои заезды» — на карте.
  На узком экране карта сверху, панель снизу. Логика диалога — чистые функции с тестами:
  `web/src/session.ts` (тела запросов к `/api/parse`), `chips.ts`, `geo.ts`; `App.tsx` держит
  состояние, `components/` только рисуют. Протокол диалога описан в плане M7.

Замеры на реальном графе (803 тыс. узлов, 1,06 млн рёбер): запрос на 3 кольца — 0,5–0,8 с;
через HTTP — 0,7–0,8 с; сборка графа 12 с; привязка 1761 сегмента 40 с; обогащение 97 с.

## Данные

Всё в `data/` (не в git). Полная пересборка с нуля:

```bash
uv run rpa fetch-region                          # data/osm/region.osm.pbf (нужны сеть и podman либо osmium-tool)
uv run rpa build-graph data/osm/region.osm.pbf   # data/graph/<sha12>-v1, симлинк current
uv run rpa import-tracks                         # data/inbox/* → data/tracks
uv run rpa match                                 # тайлы Valhalla при необходимости → data/match → rides.npy в графе
uv run rpa enrich                                # вода, лес, высоты → файлы в каталоге графа
uv run rpa eval                                  # проверка
```

- `build-graph` сам пересчитывает `rides.npy` из `data/match`; **`enrich` после пересборки графа
  нужно запускать заново**.
- В каталоге графа, кроме массивов графа: `rides.npy`, `water_nodes.npy`, `water.json`,
  `forest.npy`, `prof_off.npy`, `prof_ele.npy`, `ascent.npy`. `Engine` подхватывает то, что есть;
  без файла соответствующее предпочтение просто не действует.
- Сейчас импортирован один архив (1743 заезда, 19,4 тыс. км в регионе). Архив второго
  пользователя — положить в `data/inbox/` и повторить `import-tracks` и `match`.

## Отличия кода от исходного дизайна

Дизайн (`specs/2026-11-10-…-design.md`) писался до реализации. Фактически:

- **Генератор колец** ставит опорные точки геометрически (углы правильного многоугольника с
  привязкой к «приятному» перекрёстку), а не по полосе сетевого расстояния из SSSP. SSSP-полоса
  используется только для A→B с целевой длиной.
- **`RouteSpec` сейчас**: `start`, `end`, `shape`, `length_km`, `prefs`, `via`, `via_category`
  (только `"water"`), `avoid`, `bearing_deg`, `n_candidates`. Поля `anchor_candidate` нет:
  «вариант 2, но короче» превращается в `bearing_deg` (азимут на дальнюю точку того варианта)
  плюс новую длину.
- **Старт**: клик по карте важнее места по умолчанию (в дизайне было наоборот) — клик делается
  для конкретного запроса.
- **Тесты разбора** идут не на записанных ответах модели, а на подставной модели и на готовых
  `ParsedRequest`; живую модель проверяет `rpa nlu-eval`.
- **Газеттир** без FTS-ранжирования: точное совпадение по таблице ключей, FTS5 — только для
  совпадений по началу слов. Улиц и именованных дорог в нём нет.
- **Привязка треков**: costing `bicycle` с `ignore_oneways` и `ignore_access`, а не `pedestrian`.
- **Лес**: WorldCover читается в 1/8 разрешения (80 м) со сглаживанием 3×3 вместо полосы ±25 м
  на полном разрешении.
- **Обогащение** лежит в каталоге графа плоско, без подкаталога `enrich/`; расстояния до воды нет,
  только узлы у воды.
- **Оценка кандидата** проще, чем в дизайне: длина, повторы, отношение стоимости к длине, повороты.
- **Не сделано из запланированного для M1–M4**: барьеры на узлах; зоны избегания в весах;
  закоммиченная реальная вырезка для тестов; вывод покрытия из скоростей треков.
- **Тесты ядра** — только из Python; `cargo test` не используется.
- **Маркер старта один на всё**: клик по карте двигает его и на вкладке «Места» (там он задаёт
  точку нового места), и на вкладке «Маршрут». В `/api/parse` он уходит как `click`, только если
  его двигали после последнего результата, — иначе уточнение «короче» сбрасывало бы названный
  словами старт.
- **Правка чипов** пересобирает запрос в обстановке исходной реплики (те же `request_id`,
  `click`, `picks`), а не поверх показанного результата: так «как вариант 2» не меняет смысл.
- **Загрузка без multipart**: файл — тело `PUT`, поэтому не понадобилась зависимость
  `python-multipart`, а архив в сотни мегабайт не держится в памяти.
- **Обновление данных — команда `rpa update`**, а не скрипт: она же работает в контейнере.
- **Сохранённый маршрут нельзя переименовать**: имя — заголовок кандидата; своё имя принимает
  только API (`name`).
- **Фронтенд без компонентных тестов**: тестами покрыта логика, вёрстка и карта проверены
  прогоном в headless Chromium (Playwright ставился во временный каталог, в зависимости не внесён).

## Известные проблемы и что подстроить

- **Набор высоты, вероятно, завышен** в городе и лесу (модель поверхности видит крыши и кроны):
  374 м на 45 км по Екатеринбургу. Сверить с реальными заездами; при необходимости усилить
  сглаживание в `enrich/rasters.py::climb_m`.
- **Режим `paved`** всё ещё пропускает до ~7% «вероятно грунтовых» участков; множитель ×5 для
  `likely_unpaved` мал. Покрытие в регионе размечено плохо (явный асфальт — 11% длины дорог).
- **Маршруты «к воде»** могут дать два кольца к одному и тому же водоёму.
- **Маршрут через далёкое место** часто даёт один вариант: все объезды делят дорогу туда, и
  отбор по разнообразию их отсеивает.
- **Отсечение окончаний в газеттире грубое**: «Ключ» и «Ключи» различаются только приоритетом
  буквального совпадения. Улицы и тракты по названию не находятся.
- **«Кольцо через Ключи на 60 км»** берёт ближайшее из восьми сёл-тёзок (47 км от центра
  Екатеринбурга) без вопроса и отдаёт 95 км с пометкой: запрошенная длина при выборе места
  не учитывается, тёзки рангом ниже (деревни, урочища) не предлагаются.
- **Обработка треков всегда полная**: новый файл заново импортирует и привязывает весь inbox
  (сейчас около двух минут). Файлы из inbox не удаляются — это источник истины.
- **Прерванная обработка**: после перезапуска сервера состояние — «idle», журнал прошлого запуска
  не показывается; сам процесс `sync-tracks` при остановке сервера в контейнере погибает.
- **Привязка треков в контейнере на реальном архиве не запускалась** — проверена на микрокарте
  (загрузка со страницы → тайлы Valhalla → привязка → заезды учтены без перезапуска).
- **`rpa update` в контейнере со скачиванием** не запускался (0,2 ГБ выгрузок и растры);
  проверен с `--skip-fetch --no-rasters` на микрокарте.
- **Нет автопроверки страницы в браузере**: после правок `web/` — пересобрать и пройти руками
  запрос, уточнение, вопрос с вариантами, сохранение, GPX, теплокарту.
- **Бандл 1,3 МБ** (0,37 МБ gzip), почти весь — MapLibre; для локального сервиса терпимо.
- **Замкнутые пути** (кольцевые развязки): заезд через замыкающий узел приписывается не той дуге.
- **Числа в весах и оценке** — стартовые, по `out/eval.html` всерьёз не подбирались.
- Карты `out/eval.html` и `out/heatmap.html` глазами проверял только пользователь (M1) — после
  M2–M4 их стоит пересмотреть.

## Что дальше

План из исходного дизайна выполнен. Кандидаты на продолжение, по убыванию пользы:

1. Архив заездов второго пользователя: загрузить на вкладке «Треки».
2. Подбор чисел в весах и оценке по `out/eval.html` и по впечатлениям от реальных маршрутов;
   сверка набора высоты с реальными заездами.
3. Выбор тёзки с учётом запрошенной длины; несколько вариантов маршрута через далёкое место.
4. Инкрементальная обработка треков (привязывать только новые файлы).
5. Автопроверка страницы в браузере (Playwright) и компонентные тесты.
6. Переименование сохранённых маршрутов, удаление загруженных файлов со страницы.

## Окружение разработки

- Fedora, Python 3.14 (uv), Rust через rustup в `~/.cargo`, uv в `~/.local/bin`; `podman` есть,
  `docker` и системного `osmium-tool` нет — `fetch-region` собирает образ `rpa-osmium` сам.
- В окружении задан `HTTPS_PROXY`; httpx и rasterio берут его сами. Для cargo нужен
  `CARGO_HTTP_CAINFO` (см. `CLAUDE.md`).
- `/usr/bin/time` отсутствует — время мерить через `SECONDS` в bash.
- Node 24 LTS распакован в `~/.local/opt/node-v24.22.2-linux-x64`, ссылки `node`, `npm`, `npx` —
  в `~/.local/bin`. Зависимости фронтенда ставились с `npm install --before=2026-10-28`
  (ничего моложе двух недель). MapLibre 6 ищет свой worker рядом с собственным модулем —
  в `MapView.tsx` он подключён через `setWorkerUrl` и импорт `?url`, иначе после сборки карта пуста.
- podman есть на хосте, но не в песочнице редактора (Flatpak): оттуда он вызывается как
  `flatpak-spawn --host podman …`. Каталог `/tmp` у песочницы свой — тома монтировать из `$HOME`.
  На хосте SELinux в режиме enforcing: том нужен с `:Z` (или `--security-opt label=disable`,
  чтобы не перемечать каталог).
- Системного браузера нет. Страницу проверял headless Chromium из Playwright; ему нужно явно
  передать прокси из `HTTPS_PROXY` (логин и пароль отдельно) и исключение для `127.0.0.1`.

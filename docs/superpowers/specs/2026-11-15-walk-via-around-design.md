# Пешие участки, несколько точек, маршруты без длины, «вокруг объекта»

Дизайн этапов M9–M11. Согласован 2026-11-15. Подробные планы этапов — в
`docs/superpowers/plans/`; где они расходятся с этим файлом, прав план, а итог — в
`docs/roadmap.md`.

## Контекст

Первые пробные заезды по сервису показали четыре проблемы:

1. Нельзя задать несколько точек, через которые должен пройти маршрут.
2. Маршруты не идут через участки, проходимые пешком (пример — мост у станции Перегон);
   на карте заездов такие куски выброшены.
3. «Вокруг Верх-Исетского пруда» строит маршрут возле пруда, а не вокруг него.
4. Сервис требует длину заезда, хотя она не всегда важна.

Что показала разведка (проверено на реальных данных):

- **П. 2.** `classify_way` (`src/rpa/osm/tags.py`) выбрасывает `highway=steps`. Мост у Перегона
  (`footway`, `bridge=yes`) связан с сетью только тремя лестницами, остаётся островом и
  отсекается при оставлении главной компоненты (`osm/build.py:125-134`). Valhalla к лестницам
  привязывает: в `data/match/matched.npz` 423 пути, которых нет в графе, из них 331 лестница и
  75 пешеходных дорожек-островов. `build-graph` сам пересчитывает заезды из `matched.npz`,
  поэтому **перепривязка треков не нужна**. Теплокарта рисуется только по рёбрам графа —
  отсюда дыры.
- **П. 1.** В `RouteSpec` и `ParsedRequest` одно место `via`. `walk.route_through` уже ведёт
  маршрут через любое число узлов. На карте ставится только старт.
- **П. 3.** «Вокруг» нигде не моделируется. Указатель хранит точку и радиус равновеликого
  круга, хотя `read_places` уже строит контур через shapely.
- **П. 4.** Вопрос задаёт `nlu/resolve.py:92-94`; валидатор `RouteSpec` запрещает кольцо без
  длины; падает только `_fit_loop`. A→B и кольцо через место без длины генератор строит уже
  сейчас.

## Принятые решения

| Вопрос | Решение |
|---|---|
| Точки на карте | Без меню: клики образуют упорядоченный список, первая точка — старт, последняя — финиш, остальные — промежуточные. Маркеры перетаскиваются. Линию маршрута можно схватить и потянуть — так ставится новая промежуточная точка |
| Старые спеки в базе | Совместимость не нужна: переходника нет, история прошлых запросов старого формата очищается |
| Исполнители | Простые задачи (таблицы тегов, типы, чипы, тесты по образцу) — дешёвые субагенты (Sonnet / Haiku); генератор и геометрия — основная модель |
| Пешие участки | Все в графе, со штрафом: метр лестницы ≈ 8 м езды, хоженый ≥ 2 раз ≈ 3 м; в карточке «пешком N м», на карте пунктир |
| «Вокруг» | Любой объект с контуром из указателя (водоёмы, парки, населённые пункты); для точечных — круг |
| Кольцо без длины и без мест | Три варианта разного размера: квартили длины собственных заездов, без истории — 30 / 50 / 80 км |
| Порядок точек | Как назвал или накликал пользователь; сервис порядок не переставляет |

## Этапы

Три ветки от `main`, после каждой — остановка и отчёт (как требует `CLAUDE.md`).

### M9 — пешие участки (`m9-walk-sections`)

Самый маленький и независимый; сразу чинит карту заездов.

- `src/rpa/osm/tags.py`: `Highway.STEPS = 13`, флаг `DISMOUNT = 128`. `DISMOUNT` получают:
  лестницы всегда (в том числе с `bicycle=yes` — так размечены две из трёх у Перегона);
  `highway=corridor|platform`; `bicycle=dismount`; `bicycle=no` на footway / path / pedestrian;
  `access=no` при `foot=yes|designated|permissive` (сейчас такой путь выбрасывается).
- `src/rpa/routing/cost.py`: запись для `STEPS` в `_ROAD_CLASS_PENALTY` (без неё
  `_PENALTY_BY_CLASS` упадёт с `KeyError`); множитель ограничения `DISMOUNT_FACTOR = 8`,
  при `rides ≥ RIDES_LIFTING_RESTRICTION` — `3`. Инвариант ядра сохраняется (множитель ≥ 1,
  потолок ×50).
- `src/rpa/graph/store.py`: `FORMAT_VERSION = 2`, чтобы старый граф не подхватился.
- `routing/score.py`, `routing/path.py`, `api/schemas.py`: `walk_m` в статистике кандидата и
  пешие отрезки как диапазоны индексов координат.
- `web/`: «пешком N м» в карточке, пунктирный слой в `MapView.tsx`.
- Тесты: `tests/test_tags.py` (лестницы и платформы уходят из `NOT_ROUTABLE`, таблица флагов),
  `tests/test_build.py` + `tests/fixtures/micro.opl` (остров за лестницей входит в граф),
  `tests/test_cost.py`, `tests/test_api.py`.
- Эталон: A→B через пути у Перегона, ожидается `walk_m > 0`.

Данные: `uv run rpa update --skip-fetch` (граф → указатель → обогащение), перезапуск сервера.

### M10 — несколько точек и маршруты без длины (`m10-via-list`)

**Контракт.** `RouteSpec.via: list[Point] = []`, без переходника со старого формата. Таблицы
последних запросов и сохранённых маршрутов в `rpa.sqlite` при первом запуске новой версии
очищаются (номер схемы в `api/db.py`); сохранённые места остаются. Правило «кольцу нужна
длина» снимается.

**Генератор** (`routing/generate.py`, `routing/walk.py`):
- `route_legs` (плечи по отдельности), `_walk_via_places` вместо `_walk_via_place` — обрезка
  хвостов по границам плеч, разворот разрешён в любой из точек.
- `_passes_in_order` вместо проверки `via in arc_head` (заодно чинит случай, когда точка
  совпала со стартом).
- `_through_places`; разнообразие — `_chain_alternatives` (приём `_alternatives` на всей
  цепочке), при нехватке вариантов отбор с перекрытием до 0,6. Точка в конце единственной
  дороги по-прежнему даст один вариант.
- Длина вместе с точками: короче прямого — прямой с пометкой; длиннее — `_detours(lead=…)`
  удлиняет последнее плечо; без длины — естественная.
- `Candidate.via_label` остаётся строкой: названия через « → ».
- Три размера: `Engine.loop_sizes_km` (по умолчанию 30 / 50 / 80); `_loops` считает
  достижимость один раз и запускает по 6 азимутов на размер (54 попытки вместо 36, оценка
  ≈ ×1,3 по времени); `diversity.select_by_size` берёт по одному варианту на размер.
- Размеры из истории: `rpa match` и `build-graph` пишут рядом с `rides.npy` файл с квартилями
  длины заездов (без поездок «commute» и короче 10 км, округление до 5 км); сервер
  перечитывает его вместе с `rides.npy` (`api/app.py::_RidesFile`).

**Разбор текста** (`nlu/prompt.py`, `nlu/resolve.py`): `ParsedRequest.via: list[str]` (плоский
список, как `avoid` — строгая схема остаётся без `$defs`); правило в `SYSTEM` про «через C и D»;
`describe()` отдаёт список; вопрос о длине убирается; `_previous_points` и условие для
`bearing_deg` — под список.

**API** (`api/schemas.py`, `api/app.py`): в `/api/parse` поле `click` заменяется упорядоченным
списком `points: list[Point]`. Пустой текст с точками собирается без модели через существующий
путь `understood`.

**Роли точек** (`nlu/resolve.py`, чистая функция с тестами). Кликнутые точки занимают по
порядку те роли, которые не названы словами:
- текст ничего не называет: первая — старт, последняя — финиш (маршрут A→B), остальные —
  промежуточные; одна точка — только старт, как сейчас;
- в тексте назван старт («от дома») — все точки промежуточные, последняя — финиш;
- в тексте назван финиш или сказано «кольцо» — последняя точка тоже промежуточная;
- названные словами промежуточные места идут раньше кликнутых.

Кольцо через накликанные точки без текста: клик по маркеру старта замыкает маршрут (форма
становится «кольцо», все точки после первой — промежуточные).

**Страница** (`web/src`):
- Клик по карте добавляет точку в конец списка; при двух и более точках маршрут строится
  сразу, без текста. При ожидании ответа на вопрос и на вкладке «Места» клик работает как
  сейчас.
- Маркеры нумерованные и перетаскиваемые (MapLibre `Marker({draggable: true})`); отпускание
  перестраивает маршрут. Убрать точку — клик по маркеру или крестик чипа.
- **Перетаскивание линии маршрута**: нажатие на выбранный маршрут и движение создаёт
  временный маркер; при отпускании он становится промежуточной точкой. Место в списке
  определяется по положению вдоль маршрута: точка вставляется между теми соседями, между
  которыми лежит место захвата. Расчёт — чистая функция в `geo.ts` с тестами (индекс ближайшей
  координаты маршрута для каждой точки и для места захвата). Короткое нажатие без движения
  по-прежнему выбирает вариант.
- Любое изменение точек пересобирает запрос через `understood` — без вызова модели.
- `session.ts` несёт список точек в `Turn`; `chips.ts` — по чипу на точку; `api.ts` — типы; из
  `session.ts` уходит ветка ответа на вопрос о длине; примеры в `Chat.tsx` — с запросом без
  длины.

**Тесты и эталоны.** `test_spec`, `test_resolve` (роли точек: все четыре случая и замыкание
кольца), `geo.test.ts` (место вставки точки при перетаскивании линии), `test_generate` (две
точки по порядку, обратный порядок даёт другой маршрут, кольцо через два места без длины,
три размера по возрастанию), `test_resolve`, `test_prompt`, `test_api`, `session.test.ts`,
`chips.test.ts`. `eval/run.py::check`: точки пройдены по порядку (в пределах 500 м); три
длины различаются ≥ 20 %. Новые эталонные запросы: A→B через Дегтярск, кольцо через два места
без длины, кольцо без длины. Новые формулировки в `nlu/cases.py`.

### M11 — «вокруг объекта» (`m11-around`)

- **Указатель** (`osm/gazetteer.py`): колонка `outline` — упрощённый внешний контур крупнейшей
  части объекта, до ~100 вершин; `_merge_close` переносит контур на точку-победителя так же,
  как радиус. Реки — без контура.
- **Контракт**: `RouteSpec.around: Around{point, radius_m, outline | None}`; только кольцо;
  несовместимо с `via`, `via_category`, `bearing_deg`.
- **Геометрия** — новый модуль `routing/ring.py` на shapely (уже в зависимостях и уже загружен
  сервером): опорные точки равномерно по длине буферизованного контура, число оборотов,
  `encloses`.
- **Генератор** `_around`: 4–8 опорных точек (шаг ~4 км), привязка к «приятным» узлам вне
  объекта и не через залив; вход в кольцо там, где сумма подъезда и возврата минимальна;
  12 попыток (три отступа от берега × две фазы × два направления).
- **Проверка замыкания**: число оборотов ±1 относительно внутренней точки и ≥ 90 % вершин
  контура. Ловит срезку по плотине и восьмёрки.
- **Длина**: без длины — вплотную к объекту; с длиной — отступ подбирается аддитивно
  (масштабирование `_fit_loop` здесь не годится: длина не обнуляется при нулевом отступе).
- **Далёкий старт**: перекрытие считается только по кольцу (`Candidate.core_arcs`); если все
  варианты отбракованы лишь за повторы — отдаётся лучший с пометкой. Нет дороги с одной
  стороны — пустой результат с отдельным сообщением.
- **Разбор текста**: `ParsedRequest.around: str | None`; в `SYSTEM` — «вокруг X» для объектов
  с размером; «вокруг дома» остаётся обычным кольцом (такой эталон уже есть). `_find`
  возвращает контур вместе с местом. Чип «вокруг: X».
- **Тесты и эталоны**: `tests/test_ring.py`; сетка с дырой в `tests/helpers.py` (генератор
  тестируется на синтетической сетке, у озера в `micro.opl` дороги вокруг нет); эталоны
  «вокруг Шарташа», «вокруг Верх-Исетского пруда», он же на 60 км — контуры из указателя.

## Порядок работы

Этапы идут по порядку M9 → M10 → M11, каждый — как описано в `CLAUDE.md` («Как ведётся
работа»), с остановкой и отчётом после каждого. В плане этапа у каждой задачи помечено, какой
модели она по силам: простые задачи (таблицы тегов, типы, чипы, тесты по образцу) отдаются
дешёвым субагентам, генератор и геометрия — основной модели.

## Проверка

- Каждый этап: `uv run pytest -q`; `cd web && npm test && npm run build`; `uv run rpa eval`
  (код возврата 0, каждый запрос ≤ 5 с).
- **M9**: после `rpa update --skip-fetch` — путь моста у Перегона (OSM 35914954) есть в
  `edge_way_id.npy`; число привязанных путей вне графа падает с 423 до единиц; `ridden_km` в
  `/api/meta` вырос; `/api/heatmap` отвечает 200 (содержимое не печатается).
- **M10**: `curl --noproxy '*'` к `/api/parse` → `/api/route` для «из A в B через C и D»,
  «кольцо через Ревду и Дегтярск», «кольцо по лесу от дома»; сервер стартует на базе со
  старыми запросами и не падает; в headless Chromium — два клика дают маршрут без текста,
  перетаскивание маркера, перетаскивание линии маршрута вставляет точку в нужное место,
  удаление точки, замыкание кольца кликом по старту.
- **M11**: «вокруг Верх-Исетского пруда» без длины и на 60 км — эталон с проверкой замыкания.
- После M10 и M11 меняется промпт — `uv run rpa nlu-eval` запускает пользователь (тратит токены).

## Риски и открытые места

- Числа штрафа (8 и 3) стартовые, как и остальные веса; подстраиваются по впечатлениям.
- При далёком старте штраф ×20 за повтор рёбер может дать нелепый крюк на возврате — смотреть
  на реальном графе в M11.
- Оценка времени «три размера ≈ ×1,3» — расчётная, не измеренная.
- Перетаскивание линии на телефоне конфликтует с прокруткой карты: на сенсорном экране
  захват маршрута — долгим нажатием; проверить руками, автопроверки страницы в браузере нет.
- Каждое перетаскивание — новый запрос (~0,7 с); маршрут пересчитывается при отпускании, а
  не во время движения.

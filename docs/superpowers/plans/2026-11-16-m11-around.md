# M11. «Вокруг объекта» — план реализации

> **Для исполнителя:** скилл `superpowers:subagent-driven-development`, тест раньше кода.
> План содержит задачи, интерфейсы, тесты и команды проверки, без кода реализации.
> Дизайн: `docs/superpowers/specs/2026-11-15-walk-via-around-design.md`. Ветка `m11-around`.
> Опирается на M10 (`plans/2026-11-16-m10-via-list.md`): `Walk` с набором обязательных узлов,
> `_candidates`, кольцо без длины.

**Цель:** «вокруг Верх-Исетского пруда» строит кольцо, которое действительно обходит объект;
без длины — вплотную к нему, с длиной — шире.

**Архитектура:** указатель названий хранит упрощённый контур объекта. Разбор текста кладёт его
в `RouteSpec.around`. Генератор ставит опорные точки вдоль контура с отступом, ведёт через них
маршрут и принимает его только если ломаная обходит объект (число оборотов).

**Стек:** shapely (уже в зависимостях и уже загружен сервером), без новых пакетов.

## Общие ограничения

- Объект объезда — любой из указателя: водоём, парк, населённый пункт (контур); гора, станция
  и прочие точечные — круг. Реки — без контура, «вокруг реки» не поддерживается.
- `around` — только для кольца; несовместимо с `via`, `via_category`, `bearing_deg`.
- Схема `ParsedRequest` остаётся плоской; в модель уходят только текст и названия.
- Инвариант ядра: вес дуги равен `+inf` либо не меньше длины ребра.
- В тестах и эталонах — только публичные объекты; контуры эталонов берутся из указателя во
  время прогона, в репозиторий координаты контуров не кладутся.
- После правки промпта `rpa nlu-eval` запускает пользователь.
- Код, комментарии, коммиты — на английском; строки для пользователя — на русском.

## Модели для задач

Геометрия и генератор (задачи 1, 4, 5) — самая сильная доступная модель; указатель, контракт,
разбор текста, страница — Sonnet; реальные данные и документы — основная сессия.

### Задача 1. Геометрия кольца — *сильная модель*

Новый модуль `routing/ring.py`, чистые функции над координатами; о графе не знает.

**Интерфейс:**
- `to_local(lonlat, origin) -> xy`, `from_local(xy, origin) -> lonlat` — метры в плоскости
  вокруг `origin` (равнопромежуточная проекция, достаточная на десятках километров).
- `object_polygon(around) -> shapely.Polygon` в локальных метрах: контур, либо 16-угольник
  радиуса `radius_m` (не меньше `MIN_AROUND_RADIUS_M = 300`).
- `ring_anchors(polygon, offset_m, n, phase) -> xy[n]`: точки через равные доли длины
  внешней границы `polygon.buffer(offset_m)`, `phase` в 0..1 сдвигает начало.
- `winding_number(xy, point) -> int`.
- `encloses(coords_lonlat, around) -> bool`: число оборотов относительно внутренней точки
  равно ±1 **и** то же значение у не менее чем 90 % вершин контура
  (`ENCLOSED_VERTEX_SHARE = 0.9`).

**Тесты (`tests/test_ring.py`):** число оборотов 0, ±1, 2; восьмёрка вокруг двух точек;
опорные точки вытянутого прямоугольника лежат на расстоянии `offset_m` от него и равномерны
по длине; буфер закрывает узкий залив (точки не заходят внутрь); `encloses` — ложь для петли
рядом с объектом, для петли, срезающей угол объекта, и для маршрута «туда-обратно».

**Проверка:** `uv run pytest -q tests/test_ring.py`.

### Задача 2. Контур в указателе — *Sonnet*

**Интерфейс (`osm/gazetteer.py`):**
- `Place.outline: tuple[tuple[float, float], ...] = ()` — внешняя граница крупнейшей части
  объекта, упрощённая (`simplify` с допуском `max(30 м, 2 % радиуса)`), не больше
  `MAX_OUTLINE_VERTICES = 100` вершин (допуск удваивается, пока вершин больше); дыры
  (острова) отбрасываются. Для рек и точечных объектов — пусто.
- Колонка `outline TEXT` в таблице `places` (JSON списка `[lon, lat]`, пять знаков);
  `Gazetteer.search` возвращает `Place` с контуром.
- `_merge_close`: точка-победитель получает контур площади так же, как сейчас радиус; среди
  площадей контур — от самой большой.

**Тесты (`tests/test_gazetteer.py`):** озеро микрокарты имеет контур из её узлов; точечный
объект — без контура; населённый пункт «точка + контур» хранит контур под точкой; контур из
тысячи вершин упрощается до ≤ 100 и остаётся замкнутым простым многоугольником; река — без
контура.

**Проверка:** `uv run pytest -q tests/test_gazetteer.py tests/test_cli.py`. На реальных данных:
`uv run rpa gazetteer` — основная сессия.

### Задача 3. Контракт — *Sonnet*

**Интерфейс (`routing/spec.py`):** `Around{point: Point, radius_m: float (0..100 000), outline: list[tuple[float, float]] = []}`
(контур — не меньше 3 вершин либо пусто); `RouteSpec.around: Around | None = None`. Валидатор:
только `shape="loop"`; несовместимо с `via`, `via_category`, `bearing_deg`.
`web/src/api.ts` — тип.

**Тесты:** `test_spec.py` — допустимые и недопустимые сочетания.

**Проверка:** `uv run pytest -q tests/test_spec.py`; `cd web && npm run build`.

### Задача 4. Генератор: объезд вплотную — *сильная модель*

**Интерфейс (`routing/generate.py`):**
- `_reach(engine, w, node) -> tuple[np.ndarray, np.ndarray]` — стоимости «туда» и «обратно»
  (из них же строится нынешний `_two_way_reachable`).
- `_snap(engine, nice, usable, lon, lat, radius_m) -> int | None` — общий для
  `_polygon_vias` и `_around` шаг «узлы в радиусе → фильтр → `_nicest`».
- `_around(engine, w, start, spec) -> tuple[list[Walk], str | None]`:
  - число опорных точек `n = clip(периметр / AROUND_SPACING_M (4000), 4, 8)`;
  - узел для опорной точки: вне полигона объекта (острова исключены) и его проекция на кольцо
    — в пределах ±шаг/3 от точки (не привязываться через залив);
  - точка без узла пропускается; нужно не меньше 3 точек и ни одного разрыва длиннее 40 %
    периметра, иначе попытка пуста;
  - порядок: `[старт, a_e, a_e+1, …, a_e−1, старт]`, поворот `e` выбирается по минимуму
    `туда[a_первая] + обратно[a_последняя]`; замыкающего плеча нет; старт ближе шаг/2 к
    кольцу заменяет ближайшую опорную точку;
  - сборка `route_through`, обрезка хвостов по всему маршруту; опорные точки не обязательные
    узлы;
  - попытки в пуле потоков: отступы `AROUND_OFFSETS = (0.05, 0.25, 0.6) · r_экв` (не меньше
    150 м и не ближе 150 м друг к другу) × фаза {0, ½} × направление {по, против} — 12 штук.
- Проверка в `generate` до отбраковки: `ring.encloses(coords, spec.around)`.
- `Candidate.core_arcs: np.ndarray | None` — дуги самого кольца (без подъезда и возврата);
  `select_diverse` считает перекрытие по ним, когда они заданы.
- Без длины: оценка против `LengthKm(target = кратчайший годный, min = 0,9×, max = 2×)` —
  только в `score`; отбраковка смотрит настоящий спек.
- `Candidate.via_label` — подпись объекта («вокруг: …» формирует заголовок в `api/app.py::_body`).

**Тесты (`test_generate.py`):** `helpers.grid_with_hole(grid, i0, i1, j0, j1)` (убирает рёбра
внутренних узлов прямоугольника) и `rect_outline(...)`. Старт на «берегу»; старт под объектом;
старт в дальнем углу сетки; вытянутая дыра 2×10 клеток; объект-круг без контура; у каждого
варианта `encloses` истинно; дыра, прижатая к краю сетки (нет дороги с одной стороны), — пусто.

**Проверка:** `uv run pytest -q tests/test_generate.py tests/test_score.py`.

### Задача 5. Длина, далёкий старт, сообщения — *сильная модель*

- Заданная длина больше длины объезда вплотную: отступ подбирается аддитивно,
  `d += (target − метры) / (2π · DETOUR)`, до `MAX_FIT_ITERATIONS`; масштабирование
  `_fit_loop` здесь не годится — длина не обнуляется при нулевом отступе. Разнообразие при
  одной длине — сдвиг буферизованного кольца на ±0,3·d по четырём осям.
- Потолок отступа `3 · r_экв + 2 км`; дальше — кольцо на потолке с пометкой.
- `max` меньше объезда вплотную: объезд вплотную с пометкой «вокруг X короче N км не получится».
- Далёкий старт: если все варианты отбракованы только за повторы — отдаётся наименее
  повторяющийся с пометкой «подъезд и возврат по одной дороге».
- Пустой результат при `around`: сообщение `_NO_RING` в `api/app.py` («Объехать … не
  получается: с одной стороны нет дороги»).

**Тесты:** подгонка под длину вдвое больше объезда вплотную; пометка «короче не получится»;
далёкий старт по единственной дороге отдаёт один вариант с пометкой; `test_api.py` — сообщение.

**Проверка:** `uv run pytest -q`.

### Задача 6. Разбор текста и чип — *Sonnet*; формулировки промпта — основная сессия

**Интерфейс:**
- `ParsedRequest.around: str | None = None`. `SYSTEM`: «вокруг X» / «объехать X кругом» — для
  объектов с размером (водоём, парк, город, гора); «вокруг дома», «вокруг себя», «кружок
  вокруг» без объекта — обычное кольцо, `around = null` (эталон «круг 25 км вокруг дома» уже
  есть и не должен измениться); форма — `loop`.
- `nlu/resolve.py`: `_Found` несёт контур; `around` разрешается через `_find` с теми же
  вопросами о тёзках; `RouteSpec.around = Around(point, radius_m, outline)`. Вместе с `via` или
  «к воде» — предупреждение, `around` важнее. Река — вопрос-отказ с пояснением.
- `describe()` отдаёт `around` подписью; `_previous_points` включает его точку.
- `web/src/chips.ts`: чип «вокруг: X ✕», снятие превращает запрос в обычное кольцо.
- `nlu/cases.py`: «вокруг Верх-Исетского пруда», «кольцо вокруг Шарташа на 30 км», «объехать
  Ревду кругом», «круг 25 км вокруг дома» (без изменений).

**Тесты:** `test_resolve.py`, `test_prompt.py`, `web/src/chips.test.ts`.

**Проверка:** `uv run pytest -q`; `cd web && npm test && npm run build`.

## Риски

- Вытянутый объект с городом на берегу (как Верх-Исетский пруд): опорные точки на городской
  стороне попадают в плотную сеть улиц — маршрут может петлять. Смотреть на реальном графе.
- Нет моста через впадающую реку — объезд уходит далеко или не замыкается; тогда пустой
  результат с сообщением, это честнее кривого маршрута.
- Контур — только у объектов, размеченных площадью; посёлок-точка объезжается по кругу.

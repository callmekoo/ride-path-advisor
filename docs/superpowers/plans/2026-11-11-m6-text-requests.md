# M6. Разбор текстовых запросов — план реализации

> **Для исполнителя:** скилл `superpowers:executing-plans`, задачи по порядку, тест раньше кода.
> План содержит задачи, интерфейсы, тесты и команды проверки, без кода реализации.

**Цель:** русский текст («кольцо 45 км к воде, поменьше больших дорог», «80 км от Дидинского
тоннеля до Екатеринбурга», «короче», «не через Ревду») превращается в `RouteSpec` либо в
уточняющий вопрос.

**Архитектура:** LLM вызывается один раз и возвращает `ParsedRequest` — плоскую структуру, где
места названы строками. Всё остальное делает сервер без LLM: ищет места в газеттире, выбирает
старт, решает, задавать ли вопрос, собирает `RouteSpec`. Уточнение — тот же вызов, которому
показывают прошлый запрос в виде `ParsedRequest` и краткую статистику кандидатов.
Данные треков и координаты в LLM не уходят: только текст запроса, названия мест и длины кандидатов.

**Стек:** httpx (`trust_env=False`, прокси), SQLite FTS5, pyosmium, pydantic.

## Общие ограничения

- Прокси — только для вызовов LLM: `LLM_PROXY_URL` (http/https/socks5). Настройки:
  `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY`; читаются из окружения и из `.env` (не в git).
- Без настроенной LLM сервис работает, `/api/parse` отвечает 503 с понятным текстом.
- Тесты не ходят в сеть: HTTP — через `httpx.MockTransport`, LLM — подставной объект.
- Сообщения пользователю — на русском.

### Задача 1. Расширение `RouteSpec` и генератора

**Интерфейс:** `RouteSpec.via: Point | None` (точка, через которую надо проехать; несовместима
с `via_category`), `RouteSpec.avoid: list[AvoidArea]` (`point`, `radius_m` 100…50 000),
`RouteSpec.bearing_deg: float | None` (куда тянуть кольцо, 0 — север).

- `avoid`: рёбра, у которых хотя бы один конец в круге, получают множитель ×8 (мягко).
- `bearing_deg`: кольца строятся только по азимутам в пределах ±45°.
- `via`: кольцо = старт → место → подобранная опорная точка → старт (обобщение `_detours`
  префиксом); A→B = старт → место → финиш, с длиной — объезд на втором плече. Узел места — ближайший
  перекрёсток (степень ≥ 3) рядом с точкой, иначе ближайший узел. Если туда-обратно длиннее
  запрошенного — маршрут без подгонки длины и пометка. У кандидата `via_label` = `via.label`.

**Тесты (`tests/test_generate.py`, сетка):** кольцо через заданный узел проходит через него и
укладывается в длину; слишком далёкое место даёт пометку; A→B через точку в стороне проходит её;
`avoid` вокруг прямого пути уводит маршрут из круга; `bearing_deg=90` — центр масс каждого
кольца восточнее старта; `via` вместе с `via_category` — ошибка валидации.

### Задача 2. Газеттир

**Интерфейс (`osm/gazetteer.py`):**
- `read_places(pbf) -> list[Place]` (`name`, `alt_names`, `kind`, `lon`, `lat`, `radius_m`);
  берутся: узлы `place=*`, `railway=station|halt`, `natural=peak|…`, `tourism`, `historic`;
  площади `natural=water` (кроме технических), `leisure=park|nature_reserve`; линии
  `waterway=river`. Тёзки одного вида в одной ячейке ~5 км склеиваются.
- `build_gazetteer(places, path)`; `Gazetteer(path).search(query, near=(lon, lat), limit=8) -> list[Hit]`
  (`Hit`: `place`, `exact: bool`, `distance_km`).
- Нормализация: нижний регистр, `ё→е`, пунктуация прочь; родовые слова («озеро», «река»,
  «город», «станция», «тоннель»…) не участвуют в сравнении на точность, но дают подсказку вида.
  Порядок выдачи: точные раньше неточных, затем важность вида (город, посёлок, прочее), затем расстояние.
- Файл `gazetteer.sqlite` лежит в каталоге графа; команда `rpa gazetteer [pbf]`.

**Тесты (`tests/test_gazetteer.py`, крошечный `.opl` в `tmp_path`):** город выигрывает у
деревни-тёзки; из двух деревень ближняя первая; «озеро Круглое» и «Круглое» находят озеро;
«ё/е» и регистр; префикс («Шарташ» → «Шарташский парк») неточный; неизвестное имя — пусто;
платформа «Дидинский Тоннель» находится по «Дидинский тоннель».

### Задача 3. Клиент LLM

**Интерфейс (`nlu/client.py`):** `LlmSettings.from_env(env_file=".env") -> LlmSettings | None`;
`LlmClient(settings, transport=None).complete_json(system, user, schema_name, schema) -> dict`.
Сначала запрос с `response_format: json_schema`; если провайдер отвечает 400/422 — повтор без
него. JSON достаётся и из ответа в блоке ```` ``` ````. Ошибки сети, статуса и разбора —
`LlmError` с русским текстом.

**Тесты (`tests/test_llm_client.py`, `MockTransport`):** заголовок авторизации и модель в теле;
структурированный ответ; откат после 400; JSON внутри текста; 401 и мусор → `LlmError`;
прокси из настроек попадает в клиент, переменные окружения `HTTPS_PROXY` игнорируются;
`.env` читается, окружение важнее файла, без ключа — `None`.

### Задача 4. Промпт и `ParsedRequest`

**Интерфейс (`nlu/prompt.py`):** `ParsedRequest` — все поля необязательные: `shape`, `start`,
`end`, `via`, `via_water`, `length_km`, `length_min_km`, `length_max_km`, `avoid_major`,
`surface`, `forest`, `familiarity`, `hills`, `avoid: list[str]`, `direction` (с/св/в/…),
`toward` (место, в сторону которого ехать), `candidate` (номер варианта, на который ссылаются).
`messages(text, previous: ParsedRequest | None, candidates: list[str], place_names: list[str]) -> (system, user)`;
`describe(spec) -> ParsedRequest` — прошлый запрос на языке модели.

**Тесты (`tests/test_prompt.py`):** схема строгая (все поля в `required`, `additionalProperties: false`);
`describe` переносит длину, предпочтения, названия мест; в сообщение уточнения попадают прошлый
запрос и строки о кандидатах, но не координаты.

### Задача 5. Сборка `RouteSpec`

**Интерфейс (`nlu/resolve.py`):**
`resolve(parsed, Context(gazetteer, places, snapper, click, previous, previous_candidates, picks)) -> Resolved`
(`spec | None`, `question | None`, `warnings`). `Question`: `text`, `about` (название, о котором
спрашивают, или `"start"`), `options: list[Point]`.

- Старт: названное место (сначала сохранённые места, потом газеттир) → клик по карте → прошлый
  старт (при уточнении) → место по умолчанию → вопрос.
- Неоднозначность: точных совпадений несколько, самое важное не единственное в своём классе и
  ближайшее не вдвое ближе следующего → вопрос с вариантами; ответ приходит в `picks`.
  Совпадений нет → вопрос без вариантов. Только неточные → вопрос с вариантами.
- Длина: «около N» → ±10%; диапазон → жёстко; кольцо без длины → вопрос.
- `direction`/`toward`/`candidate` → `bearing_deg` (для варианта — азимут на его дальнюю точку).
- `avoid` → круг, радиус по виду места (город 5 км, посёлок 2,5 км, прочее 1,5 км).
- Место дальше 500 м + радиус объекта от дорог → предупреждение.

**Тесты (`tests/test_resolve.py`, сетка + газеттир из задачи 2):** каждый пункт выше отдельным тестом.

### Задача 6. `POST /api/parse`

Тело: `{text, click?, request_id?, picks?}`. Ответ: `{spec | null, question | null, understood, warnings}`.
`create_app(engine, db_path, gazetteer=None, llm=None)`. Без LLM — 503; ошибка LLM — 502.

**Тесты (`tests/test_api.py`):** подставной LLM → `spec`, который принимает `/api/route`;
вопрос о старте; уточнение по `request_id` показывает модели прошлый запрос; 503 без LLM.

### Задача 7. Эталонные формулировки и живая проверка

`nlu/cases.py`: ~40 формулировок (три из постановки, длины, покрытие, лес, холмы, вода,
направления, «от … до …», уточнения) с ожидаемыми полями `ParsedRequest`.
`rpa nlu-eval` прогоняет их через настроенную LLM, печатает расхождения, код возврата 1 при доле
совпадений ниже 90%. **Запускается, когда пользователь даст адрес, модель, ключ и прокси.**

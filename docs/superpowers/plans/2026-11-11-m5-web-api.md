# M5. Веб-API — план реализации

> **Для исполнителя:** скилл `superpowers:executing-plans`, задачи по порядку, тест раньше кода.
> По соглашению из `CLAUDE.md` план содержит задачи, интерфейсы, тесты и команды проверки,
> но не код реализации.

**Цель:** HTTP-сервис, который по `RouteSpec` отдаёт 2–3 кандидата с геометрией, статистикой и
профилем высот, выгружает любой из них в GPX и хранит сохранённые места.

**Архитектура:** FastAPI-приложение собирается фабрикой `create_app(engine, db_path)` — движок и
путь к базе передаются снаружи, поэтому тесты идут на синтетической сетке без данных на диске.
Обработчики синхронные (FastAPI сам выносит их в пул потоков; ядро отпускает GIL). SQLite хранит
места и последние запросы с кандидатами, чтобы ссылка на GPX пережила перезапуск, а M6 мог
достать предыдущий `RouteSpec` для уточнения.

**Стек:** FastAPI, uvicorn, stdlib `sqlite3`, pydantic; тесты — `fastapi.testclient.TestClient`.

## Общие ограничения

- Логинов нет; сервер по умолчанию слушает `127.0.0.1`.
- Все сообщения пользователю — на русском; код и комментарии — на английском.
- `RouteSpec` не меняется: тело `POST /api/route` — это он и есть.
- В тестах только публичные и синтетические координаты.
- Координаты в ответах — `[lon, lat]`, 6 знаков; геометрия — GeoJSON `LineString`.

### Задача 1. GPX

**Интерфейс:** `to_gpx(coords: f64[P,2] lon/lat, name: str, profile: tuple[dist_m, ele_m] | None) -> str`.
Один `<trk>` с одним `<trkseg>`; при наличии профиля каждой точке ставится `<ele>` —
интерполяция профиля по расстоянию вдоль `coords` (длина линии нормируется к длине профиля).

**Тесты (`tests/test_gpx.py`):**
- результат разбирается `xml.etree`, корень `gpx` версии 1.1 в пространстве имён
  `http://www.topografix.com/GPX/1/1`, число `trkpt` равно числу точек, `lat`/`lon` на месте;
- имя с `<&>` экранируется и читается обратно без искажений;
- без профиля тегов `ele` нет; с линейным профилем 100→200 м у первой точки 100, у последней 200,
  у средней точки прямой линии — 150.

### Задача 2. База

**Интерфейс (`api/db.py`):** класс `Db(path)`; соединение на вызов, WAL, схема создаётся при
первом открытии.
- `places() -> list[dict]`, `add_place(name, lon, lat, is_default=False) -> dict`,
  `update_place(id, **fields) -> dict | None`, `delete_place(id) -> bool`,
  `default_place() -> dict | None`. Имя уникально без учёта регистра → `DuplicateName`.
  Место по умолчанию ровно одно: первое созданное становится им само; установка флага снимает
  его с остальных; при удалении места по умолчанию флаг переходит к самому старому из оставшихся.
- `save_request(spec_json: str, candidates: list[str]) -> tuple[int, list[int]]` — id запроса и
  id кандидатов по порядку; `candidate(id) -> str | None`; `request(id) -> dict | None`
  (`spec`, `candidates`). Хранится не больше `KEEP_REQUESTS = 200` последних запросов, старые
  удаляются вместе с кандидатами.

**Тесты (`tests/test_db.py`, база в `tmp_path`):** правила места по умолчанию (три случая выше);
дубликат имени в другом регистре; изменение и удаление несуществующего; кандидат читается по id;
после 201-го запроса первый запрос и его кандидаты исчезают; данные переживают новое `Db(path)`.

### Задача 3. Приложение и маршруты

**Интерфейс:** `create_app(engine: Engine, db_path: Path) -> FastAPI`.

- `GET /api/meta` → `{nodes, edges, road_km, bbox [w,s,e,n], has_rides, ridden_km, has_water, has_terrain}`.
- `POST /api/route` (тело — `RouteSpec`) → `{request_id, spec, candidates[], warnings[], message}`.
  Кандидат: `{id, geometry, length_km, ascent_m | null, score, note, via_label, features{…},
  km_by_highway, km_by_surface, profile {distance_m[], elevation_m[]} | null}`.
  Профиль прореживается до ≤ 500 точек.
  - старт или финиш дальше `MAX_SNAP_M = 2000` от дорог графа → 422 с русским текстом;
  - дальше `FAR_SNAP_M = 500` → строка в `warnings`;
  - кандидатов нет → 200, пустой список и `message` с объяснением (в том числе «в графе нет
    данных о воде», если просили воду, а обогащения нет).
- `GET /api/candidates/{id}.gpx` → `application/gpx+xml`, `Content-Disposition: attachment`,
  имя файла `route-<id>.gpx`; неизвестный id → 404.
- `GET/POST /api/places`, `PUT/DELETE /api/places/{id}`; дубликат имени → 409, нет такого → 404.

**Тесты (`tests/test_api.py`, `TestClient`, `grid_engine`, база в `tmp_path`):**
- `/api/meta`: размеры сетки, `has_rides` ложно;
- кольцо 8 км из центра сетки: ≥ 2 кандидата, длины в допуске, геометрия замкнута, id различны,
  `request_id` есть; повторный запрос даёт новые id;
- A→B без длины: первая точка геометрии у старта, последняя у финиша;
- неверный `RouteSpec` (кольцо без длины) → 422;
- старт в 50 км от сетки → 422 с текстом про покрытие; в 1 км от сетки → 200 и предупреждение;
- вода без обогащения → 200, пусто, `message` упоминает воду;
- GPX существующего кандидата разбирается и содержит столько точек, сколько геометрия; 404 для чужого id;
- места: создать, получить список, сделать другое местом по умолчанию, дубликат → 409, удалить, 404.

### Задача 4. Команда `serve`

`rpa serve [--host 127.0.0.1] [--port 8000] [--graph DIR]`: `load_engine`, `create_app`,
`uvicorn.run`. `config.db_file()` → `data/rpa.sqlite`. Без графа — понятная ошибка и код 1.

**Тест (`tests/test_cli.py`):** `serve` без графа выходит с кодом 1 и сообщением.

### Задача 5. Проверка на реальных данных и документы

```bash
uv run pytest -q                 # всё зелёное
uv run rpa eval                  # пороги не просели
uv run rpa serve &               # затем:
curl -s localhost:8000/api/meta
curl -s -X POST localhost:8000/api/route -H 'content-type: application/json' \
  -d '{"start":{"lon":60.6057,"lat":56.8380},"shape":"loop","length_km":{"target":45,"min":40.5,"max":49.5},"via_category":"water"}'
curl -s localhost:8000/api/candidates/1.gpx | head
```

Ожидается: 2–3 кандидата меньше чем за 2 с, GPX проходит разбор `gpxpy`-совместимым парсером
(`xml.etree` + проверка пространства имён), профиль высот не пуст.
Обновить `docs/roadmap.md`, `README.md`, `CLAUDE.md` (команда `serve`).

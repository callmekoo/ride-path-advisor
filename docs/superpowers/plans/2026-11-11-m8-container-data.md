# M8. Контейнер, треки через веб, обновление данных — план реализации

> **Для исполнителя:** скилл `superpowers:executing-plans`, тест раньше кода.
> План содержит задачи, интерфейсы, тесты и команды проверки, без кода реализации.

**Цель:** сервис ставится одной сборкой образа и одной командой запуска; новые заезды
добавляются со страницы и учитываются без перезапуска; карта и граф обновляются одной командой.

**Архитектура:** сервер по-прежнему не загружает Valhalla. Загруженные файлы ложатся в
`data/inbox`, обработку (`import-tracks` + `match`) ведёт отдельный процесс `rpa sync-tracks`,
запущенный сервером; он атомарно заменяет `rides.npy`, а сервер замечает новый файл по времени
изменения и подменяет счётчики заездов. Образ один — и для сервера, и для пакетных команд.

**Стек:** FastAPI (тело загрузки читается потоком, без multipart), `subprocess`, podman;
образ: uv + rustup → node → `python:3.14-slim` с `osmium-tool`.

## Общие ограничения

- Логинов нет: загрузка файлов доступна всем, кто видит сервис. Наружу — только за VPN.
- Файлы треков не покидают `data/`; в журнале обработки — только счётчики и имена файлов.
- В тестах обработку заменяет подставная команда; Valhalla и сеть не нужны.
- После пересборки графа (`rpa update`) сервер нужно перезапустить: массивы графа он держит в памяти.

### Задача 1. Заезды без перезапуска

`Engine.set_rides(rides | None)` (проверяет длину). `create_app(..., rides_path=None)`: перед
`/api/route`, `/api/meta`, `/api/heatmap` сервер сверяет время изменения файла; если он новый —
читает, подменяет счётчики, сбрасывает собранную теплокарту и пересчитывает `meta`. Файл исчез —
счётчики остаются прежними.

**Тесты (`tests/test_api.py`):** после замены файла `meta.ridden_km` и `/api/heatmap` меняются
без пересоздания приложения; файл с чужой длиной не ломает сервер (старые счётчики, запись в лог).

### Задача 2. Загрузка и обработка треков

**Интерфейс:**
- `PUT /api/tracks/files/{name}` — тело запроса и есть файл. Имя: без каталогов и ведущей точки;
  расширения `.zip`, `.gpx`, `.fit`, `.tcx` и те же с `.gz`. Пишется во временный файл с точкой в
  начале имени и переименовывается. 201 `{name, size}`; 400 — имя или тип; 413 — больше 4 ГБ;
  409 — идёт обработка.
- `POST /api/tracks/import` — 202 и состояние; 409, если уже идёт.
- `GET /api/tracks` → `{state: idle|running|done|failed, started, finished, log: [последние 20 строк], inbox: [{name, size}]}`.
- `Meta.can_import_tracks`. Без `TrackImport` (тесты, чистый API) эндпоинтов треков нет: 404.
- `rpa sync-tracks` = `import-tracks`, затем `match`. Сервер запускает `python -m rpa sync-tracks`,
  вывод — в `data/jobs/tracks.log`.
- `import_inbox` пропускает файлы, имя которых начинается с точки.

**Тесты:** `tests/test_jobs.py` — приём файла, отказ по имени и типу, обрезанная загрузка не
оставляет мусора, успешная и неуспешная команда, повторный запуск во время работы;
`tests/test_api.py` — тот же круг через HTTP; `tests/test_cli.py` — `sync-tracks` без inbox
объясняет, что делать; `tests/test_tracks.py` — файл с точкой пропущен.

### Задача 3. Вкладка «Треки»

Видна при `can_import_tracks`. Пояснение, как получить архив Strava; выбор нескольких файлов;
«Загрузить и обработать»: файлы по очереди → `POST /api/tracks/import` → опрос раз в 2 с →
по завершении обновить `meta` и сбросить загруженную теплокарту. Показывает ход загрузки, хвост
журнала, итог, сколько километров дорог проехано. Флажок «Мои заезды» переезжает на карту —
в шапке панели для четвёртой вкладки нет места.

**Проверка:** `npm test`, `npm run build`, прогон в браузере.

### Задача 4. `rpa update`

`fetch-region` → `build-graph` (сам пересчитывает заезды из `data/match`) → `gazetteer` →
`enrich`; в конце напоминание перезапустить сервер. `--skip-fetch` — пересобрать из уже скачанного.

**Тесты (`tests/test_cli.py`):** `update --skip-fetch` на микрокарте (без растров) строит граф и
указатель; без скачанного файла объясняет, что делать.

### Задача 5. Образ

`Containerfile`: стадия сборки (uv, rustup, `uv sync --frozen --no-dev --no-editable`), стадия
`node:24` (`npm ci && npm run build`), итог — `python:3.14-slim` + `osmium-tool`, `.venv` и
`web/dist`; `RPA_DATA_DIR=/data`, `RPA_WEB_DIR=/app/web`; `ENTRYPOINT ["rpa"]`,
`CMD ["serve", "--host", "0.0.0.0"]`. `.containerignore` исключает `data/`, `out/`, `.env`, `.git`,
сборочные каталоги.

**Проверка:** `podman build -t rpa .`; `podman run --rm rpa --help`; сервер на реальных данных
(`-v ./data:/data`, `--env-file .env`), `curl /api/meta`, маршрут через `/api/route`, страница.

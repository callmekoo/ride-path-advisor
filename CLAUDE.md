# ride-path-advisor

Личный сервис: по текстовому запросу строит велосипедные маршруты по графу OSM,
предпочитая дороги из собственной истории заездов. Два пользователя, один регион
(Свердловская область + 100 км), без логинов.

## С чего начать новую сессию

1. Прочитать [`docs/roadmap.md`](docs/roadmap.md): что сделано, что дальше, известные проблемы,
   отличия кода от исходного дизайна.
2. Исходный дизайн и принятые решения: [`docs/superpowers/specs/2026-11-10-ride-path-advisor-design.md`](docs/superpowers/specs/2026-11-10-ride-path-advisor-design.md).
   Где он расходится с `docs/roadmap.md`, прав roadmap.
3. Проверить состояние: `git log --oneline | head`, `uv run pytest -q`, `uv run rpa --help`,
   `cd web && npm test`.

## Как ведётся работа

- Этап (M5, M6, …) = ветка `mN-<тема>` от `main`. По завершении — локальное слияние
  fast-forward в `main` и удаление ветки (так пользователь выбирал каждый раз; пуш на GitHub
  только по явной команде).
- **После каждого этапа останавливаться и отчитываться** — пользователь бережёт лимиты.
- Порядок на этап: скилл `superpowers:writing-plans` → план в `docs/superpowers/plans/` →
  `superpowers:executing-plans` → тест раньше кода → проверка на реальных данных
  (`rpa eval`) → `superpowers:finishing-a-development-branch`. План — задачи, интерфейсы,
  тесты и команды проверки, без дублирования кода реализации.
- По завершении этапа обновлять `docs/roadmap.md` и раздел «Состояние» в `README.md`.
- Общение с пользователем и документация — на русском; код, комментарии, сообщения
  коммитов — на английском.
- Коммиты заканчиваются строкой `Co-Authored-By`, как в истории репозитория.

## Команды

```bash
export PATH=$HOME/.cargo/bin:$HOME/.local/bin:$PATH
export CARGO_HTTP_CAINFO=/etc/pki/ca-trust/extracted/pem/tls-ca-bundle.pem  # иначе cargo падает за прокси
uv sync                # зависимости + сборка Rust-ядра
uv run pytest -q       # все тесты, ~5 с
uv run rpa eval        # эталонные запросы на реальном графе → out/eval.html; код возврата 1 при провале порогов
uv run rpa serve       # страница и API на 127.0.0.1:8000; curl к нему — с `--noproxy '*'`
uv run rpa gazetteer   # указатель названий из OSM → gazetteer.sqlite в каталоге графа
uv run rpa nlu-eval    # эталонные формулировки на живой модели (нужен .env, тратит токены)
uv run rpa sync-tracks # data/inbox → заезды по рёбрам (то же делает вкладка «Треки»)
uv run rpa update      # свежий OSM → граф → указатель → вода, лес, высоты; затем перезапустить сервер

cd web                 # фронтенд; Node 24 лежит в ~/.local/bin
npm install            # новые зависимости — с `--before=<дата двухнедельной давности>`
npm test               # vitest: логика диалога, чипы, геометрия
npm run build          # проверка типов и сборка в web/dist — её раздаёт `rpa serve`

podman build -t rpa .  # образ; из песочницы редактора — `flatpak-spawn --host podman …`
```

Полный конвейер данных — в `docs/roadmap.md`, раздел «Данные».

## Устройство (кратко)

- `kernel/` — Rust (PyO3): A* и поиск до всех узлов по вектору весов дуг. О тегах и
  предпочтениях ничего не знает. Тестируется только из Python (`tests/test_kernel.py`).
- `src/rpa/osm` — сборка графа из pbf; `graph` — формат на диске; `tracks` — импорт заездов;
  `match` — привязка к дорогам (Valhalla) и подсчёт заездов по рёбрам; `enrich` — вода, лес, высоты;
  `routing` — `RouteSpec` → веса → генератор → оценка → отбор; `eval` — эталонные запросы;
  `nlu` — текст → `ParsedRequest` (LLM) → `RouteSpec` или вопрос (без LLM);
  `api` — FastAPI-приложение, SQLite (места, последние запросы, сохранённые маршруты) и
  `jobs.py` (приём файлов треков и запуск их обработки отдельным процессом);
  `viz` — отладочные HTML-страницы; `cli.py` — команды `rpa`.
- `web/` — страница: `src/api.ts` (типы и вызовы API), `session.ts` / `chips.ts` / `geo.ts`
  (чистая логика с тестами), `App.tsx` (состояние), `components/` (только отрисовка).
- Дуга `a = 2·e + d` (`d = 0` — по направлению OSM-пути): `reverse(a) = a ^ 1`, `edge(a) = a >> 1`.
- Инвариант ядра: вес дуги равен `+inf` либо не меньше длины ребра в метрах.
- Центральный контракт — `RouteSpec` (`src/rpa/routing/spec.py`): его производят разбор текста
  и интерфейс, движок читает только его.

## Чего не делать

- Не коммитить `data/`, `out/`, треки, `.env`, личные координаты (в тестах и эталонных
  запросах — только публичные точки).
- Не отправлять данные треков в LLM и во внешние сервисы. В модель уходят только текст запроса,
  названия мест и статистика вариантов; координаты — нет.
- Не читать и не печатать `.env`: там ключ LLM.
- Не рассматривать снимки экрана и выгрузки с включённой теплокартой и не печатать `/api/heatmap`:
  это история заездов. Проверять слой по косвенным признакам (код ответа, легенда).
- Не использовать Strava API (политика 2026 года запрещает хранение и агрегацию) — только архив
  «Скачать свои данные».
- Не проверять загрузку треков и `sync-tracks` на настоящем `data/`: пробный файл попадёт в
  историю заездов. Для этого — отдельный каталог данных с микрокартой (`RPA_DATA_DIR`).
- Не запускать `cargo test` (не линкуется без `python3-devel`) и `python -m valhalla …`
  (обёртка молча ничего не делает — бинарники вызываются напрямую, см. `match/matcher.py`).
